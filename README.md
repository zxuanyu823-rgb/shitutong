# 视图通 —— 基于三维联动与错因诊断的工程制图学习智能体

当前版本 **1.8.5**（安卓安装包见 Releases）。

**拍照建模**：拍一道三视图题，视觉模型识别图线 → 程序用长对正、高平齐、宽相等对齐纠错 → 自动重建三维形体 → 反算三视图与照片逐线比对打分 → 不吻合时把差异交给大模型修改方案再校验。只给两个视图的补图题会补画第三视图，多解时全部列出。重建后的模型可以直接用于联动讲解和出题。

三维模型与三视图双向联动：在视图里点一条线，三维模型上对应的棱/面同步高亮，并画出“长对正、高平齐、宽相等”的投影连线；问“为什么这里是虚线”，智能体会把模型转到该视图方向、打开透视、标出挡住它的面，再结合国家标准讲解。练习题由程序根据几何计算自动生成，答案可验证，错题按错因归类统计。

## 本地运行

需要 Node.js 18 或更高版本。

```bash
cd server
cp config.example.json config.json   # 按需填写
node server.js
```

浏览器打开 http://localhost:8080 。没有填大模型时自动使用“离线讲解”，所有联动、讲解和练习功能照常可用。

## 配置（server/config.json）

| 字段 | 说明 |
|---|---|
| PORT | 端口，默认 8080 |
| LLM_BASE_URL | OpenAI 兼容接口地址。DeepSeek：`https://api.deepseek.com`；通义千问：`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| LLM_MODEL | 模型名，如 `deepseek-chat`、`qwen-plus`（以服务商控制台当前提供的为准） |
| LLM_API_KEY | 接口密钥，只放在服务器上，不会发到浏览器 |
| REVIEW_USER / REVIEW_PASS | 评审账号密码。填了密码就会开启登录页 |
| SESSION_SECRET | 一串随机长字符，用于登录签名 |
| VISION_MODEL | 拍照识图用的视觉模型，如 Kimi 的 `kimi-k3`、通义的 `qwen3-vl-plus`（以控制台为准）。不填则拍照识图不可用，其余功能照常 |
| VISION_BASE_URL / VISION_API_KEY | 视觉模型和对话模型不是同一家时填写（例如对话用 DeepSeek、识图用通义），否则留空沿用 LLM 的 |
| SEARCH_API_KEY | 博查 Web Search API 密钥，用于“搜相似例题”；不填则不显示联网搜索 |

模型名称经常更新，填写前到服务商控制台确认当前可用的名称。

## 部署到评审能访问的服务器

评审在国内访问，网页和大模型接口都要放在国内能直接打开的地方。时间紧的推荐做法：

1. 买一台**香港地域**的轻量应用服务器（阿里云、腾讯云都有，学生有优惠），系统选 Ubuntu。香港节点不需要 ICP 备案，大陆可以直接访问。
2. 安装 Node.js：`curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs`
3. 把整个文件夹上传到服务器（如 `/opt/shitutong`），在 `server/` 里写好 `config.json`。
4. 后台运行：`cd /opt/shitutong/server && nohup node server.js > run.log 2>&1 &`（或用 pm2）。
5. 在云控制台的**防火墙**里放行 8080 端口。
6. 提交给评审的链接：`http://服务器IP:8080`，并附上评审账号和密码。

如果用大陆服务器并绑定域名，需要先完成 ICP 备案，来不及就直接用 IP 加端口访问。

## 拍照建模的范围与评测

- 适用：平面立体（含斜面、一般位置平面切角）、轴线与坐标轴平行的圆孔和圆柱、圆角板与相切的支撑板、凸台和肋板，即教材中大部分组合体题。
- 程序重建的三步：①外轮廓沿投射方向拉伸求交；②视图中位于轮廓内的圆识别为孔，深度由另两个视图中 c±r 处的线确定；③仍有差异时，按未吻合图线的坐标做“挖切搜索”和“斜面切割搜索”；④仍不吻合时进入下面的“形体分析建模”。
- 有原照片和多模态模型时，还会做三道把关：①识图自检：把识别结果重新画出来和照片一起交给模型改错；②联网检索相似题（Tavily/博查），摘要作为重建参考；③照片核对：每个候选形体反算出三视图，和原照片对照，不一致就带着问题清单让模型看图修改。另外让模型直接看照片建一个方案，与程序候选一起比较。
- **算法量线**：视觉模型只负责“认”出有哪些线、属于哪个视图、大概在哪；每条线的精确位置、端点、虚实和各视图的统一比例由图像算法按照片像素量出来（web/js/recon/cv.js），并自动转正倾斜的照片。墨迹过密或大部分线找不到时自动沿用模型读数。同时以照片为准纠正大模型的读数：照片里找不到墨迹的线（大模型“脑补”的）不拿去建模，照片里有墨迹却没被识别的线由程序从墨迹里补上。量线结果会叠加显示在题目照片上（绿色为量到的线，蓝色为程序补上的线，红色虚线为照片里没有、已去掉的线）。合成照片评测见 `eval/cv-results.md`（标准条件下重建成功 0/60 → 59/60，照片带尺寸标注时 0/36 → 35/36）。
- **形体分析建模**（web/js/recon/parts.js）：程序候选不吻合时，不再让大模型一次写出整个形体的建模步骤，而是按教材的“形体分析法”只列出组成部分——底板、支撑板、肋板、圆筒、凸台叠加，孔、槽挖切；每个部分说明在哪个视图反映实形、轮廓顶点、沿投射方向的范围。几何全部由程序完成：坐标吸附到量好的图线上；圆角板、与圆柱相切的支撑板用“顶点 + 圆的凸包”表示，切点由程序计算；每个部分的范围在相邻坐标里试、补上程序识别到的圆孔、去掉多余部分，挑与三视图最吻合的。仍有差异时把差异按同样的坐标交给大模型修改部件清单。用模拟回答测试：轴承座压轴题一份基本正确的部件清单可达 99.5%（原来直接写建模步骤约 59%），一份漏了肋板、范围写错的清单经程序微调从 77% 升到 90%，再修正一轮 98%。真实效果取决于大模型能否把部件认对，需要实拍验证。
- **程序补齐**（parts.js `fillGaps`）：大模型常把肋板只写到圆筒前面，压在圆筒下面、连到支撑板的那段漏掉，侧面看是空心的。不论候选来自形体分析还是看图直接建模，程序都会检查叠加体朝外的面：它在视图里正好是一条多出来的线、或者往外长一段正好补上缺少的线，就把形体沿这个面长到下一个坐标值或碰到别的形体为止，几种长法都反算比对，留吻合度最高的。
- 耗时控制：程序候选 6 秒内没算完就让大模型同时开始建模；程序的挖切搜索最多 40 秒；AI 照片复核只复核图线吻合度最高的候选，并用最快的思考强度（识图、建模才用设置里的强度，自检最多“均衡”）；修正最多两轮，一轮没有提高或已基本吻合就停。
- 建模语言新增“凸包柱体”：柱体可带 `circles`，截面取顶点和圆的凸包，相切处与圆柱网格严丝合缝，三视图在切点处不会多画线（符合“相切处不画线”）。
- 识图难免有误差，识别后可以在图上点线修改（实线 → 虚线 → 点画线 → 删除）再重新生成。
- 算法量线评测：启动本地服务器后打开 `/test/` 页面点“开始评测”，合成带倾斜、模糊、噪声的题目照片和带误差的模型读数，对比两种做法的重建成功率。
- 离线评测：`./tools/run-eval.sh`，用题库模型生成模拟识图结果（可加坐标噪声和各视图比例误差），比较重建结果与原模型的三视图。结果见 `eval/results.md`。注意这是程序对程序的测试，只说明重建算法本身，不代表真实照片的识别准确率；真实照片的效果需要用实拍题目另测。

## 技术路线（写 PPT 用）

```
参数化题库（叠加/切割描述）
   → Manifold 布尔运算生成实体网格
   → 按二面角提取面与棱，面按朝向分类（水平面/正垂面/一般位置平面…）
   → 三个方向正投影 + 沿视线射线检测，逐段判定可见性（实线/虚线）
   → 共线合并，按“可见 > 不可见 > 中心线”处理重合
   → 建立 2D 线 ↔ 3D 棱/面 对应表、遮挡面表
   → 讲解引擎 / 练习生成 / 大模型工具调用 都基于这张表
```

大模型不直接“看图猜形状”，而是通过 10 个工具（查询元素、查询遮挡、高亮、转视角、透视、展开动画、检索知识库、联网搜例题、切换模型、出题）获取程序计算的事实再讲解，避免几何幻觉。

## 安卓 App

`android/` 是安卓版：用系统 WebView 运行同一套网页，网页文件打包在安装包里，不需要服务器。
- 大模型、识图和搜索请求由 App 原生发出，不受浏览器跨域限制。
- 在 App 的“设置”里填写：服务商（DeepSeek / Kimi K3 / 通义）、接口地址、对话模型、API Key，以及 Tavily API Key（联网搜例题）。密钥只保存在手机上。
- 拍照识图可以单独选服务商，比如对话用 DeepSeek、识图用 Kimi K3（模型名 `kimi-k3`；国际版接口 `https://api.moonshot.ai/v1`，中国版 `https://api.moonshot.cn/v1`，密钥不通用）。Kimi K3 的 temperature 等参数是固定的，程序会自动不传；看图时思考强度用 high，对话用 low。
- 拍照建模的“拍照 / 选图”打开系统相册或文件选择器，先用相机拍好题目再选。
- “设置”里还可以换界面背景、调字体大小（小 / 标准 / 大 / 特大，或拖动滑块 80%～140%）。App 不再跟随系统字体缩放，避免手机上布局挤乱。
- **切后台、锁屏也能继续**：识图建模、对话改模型期间，App 会启动一个前台服务（通知栏显示“视图通正在工作”和当前步骤），保持网络和计算不被系统冻结；完成时如果你不在 App 里，会发一条通知。第一次使用时请允许“通知”权限。部分国产系统还需要在“电池 / 后台管理”里把视图通设为“允许后台运行”。
- **快速模式（默认）**：大模型看完照片后，先由程序按像素量线核对；量线与照片吻合就跳过大模型自检，重建出的候选与量过的图线完全吻合时也跳过 AI 照片复核（可手动点“让 AI 对照照片复核”）。顺利时只需调用一次看图模型，比“仔细”模式快 2～4 倍。量线发现可能读错或漏读时，会自动回到完整流程。可在“设置 → 拍照建模流程”切换。
- 识图失败时，提示里会写明原因：“连接被中断 / 等待超时”是网络问题（开着代理时换个节点或暂时关掉，等待时别切到后台），不用重拍；“接口返回 401/402/404”是密钥、余额或模型名称的问题，去“设置”里核对。长回答（识图、改模型）用流式返回，网络中断会自动重试一次。
- `测试题/` 里有一道带答案的测试题（三视图图片、可打印的 PDF、答案三维图和 STL），可以拿来试拍照建模。
- `测试题/梯度三题/` 是由易到难的三道题（简单：台阶孔块；中等：斜面导块；较难：圆头支座），题目图片和打印用 PDF 在外层，答案（三维图、STL、形体描述）放在 `答案/` 里，测试前先别看。
- `测试题/压轴题/` 是一道本科组合体压轴难度的轴承座（圆角底板 + 底面通槽、与圆筒相切的支撑板、肋板、带孔凸台与圆筒相贯），程序自动候选只能到约 75%，其余要靠大模型在修正环节写出建模步骤。
- 重新打包：`android/build.sh`（需要 JDK 和 Android SDK 的 build-tools 35、platform 34，不需要 Gradle）。`release.keystore` 是签名文件，以后升级必须用同一个，不要丢。
